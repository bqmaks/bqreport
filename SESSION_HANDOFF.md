# SESSION_HANDOFF

Состояние на 2026-08-14.

## Что это

Пакет переписывается с нуля. Репозиторий был очищен коммитом
`2a83050`; прежняя реализация (~230 файлов) доступна в истории начиная с
`fc07399` и ниже — как справочник, но **не как контракт**.

`AGENTS.md` описывает **старый** пакет и пока не переписан. Не считать его
действующим контрактом: конкретные имена функций, схемы плана и инварианты
оттуда относятся к удалённой реализации.

## Порядок работы

Пользователь читает каждую строку кода лично. Отсюда:

- один логический шаг за раз — одна функция или один небольшой файл, затем
  остановка и разбор;
- сначала намерение и сигнатура, потом код;
- никаких попутных рефакторингов и скрытых хелперов;
- коммит только по явной просьбе;
- перед разбором — фактическая проверка (запуск, а не рассуждение).

## Принятые решения

Эти вопросы закрыты, переигрывать без нового повода не нужно.

| Решение | Выбор |
|---|---|
| Архитектура | компилятор плана: `plan → validate → run` |
| Хранение метаданных | реестр в атрибуте tibble (`bq_data`) |
| Идентификаторы | порядковые `v001`, без хешей и без `digest` |
| Зависимости | минимум; сейчас `dplyr`, `tibble` |
| Хранение при разметке | **не конвертируется**; приведение делает движок при анализе |
| `mutate()` по столбцу | сбрасывает `type`, сохраняет `label` и `role` |
| `group_by()` | запрещён на `bq_data` (типизированная ошибка) |
| Тип 3+ категорий | `nominal`, не `multinomial` (тип ≠ модель) |
| `indicator` | отдельный тип для 0/1 и TRUE/FALSE; у него событие самоочевидно, у `binary` его надо выбрать |
| Непрерывный тип | `continuous`, не `numeric` (маскировал бы `base::numeric`) |
| `count` | никогда не выводится автоматически, только явно |
| Ошибки | базовые типизированные условия `bq_error_*`, без `cli` |
| Печать | через `tibble::tbl_sum()`, своего `print` нет |

## Сделано

- `R/conditions.R` — `bq_abort()`, типизированные условия.
- `R/bq-data.R` — `as_bq_data()`, конструкторы `bq_data` и реестра.
- `R/registry.R` — согласование реестра со столбцами, выдача идентификаторов.
- `R/dplyr-methods.R` — сохранение метаданных через dplyr.
- `R/variables.R` — `variables()`, чтение реестра.
- `R/print.R` — заголовок со сводкой по ролям.
- `R/infer-type.R` — `infer_type()`, вывод аналитического типа из вектора.

Реестр сейчас: `var_id`, `name`, `label`, `role`, `type`.

127 тестов, `R CMD check` — Status: OK.

## Следующий шаг

Шаг 6: конструкторы типов и сеттеры.

- `continuous()`, `count()`, `binary(event = )`, `indicator()`,
  `ordinal(levels = )`, `nominal(reference = )` — конструкторы, раскрывающиеся
  в плоские колонки реестра (не list-column: реестр должен оставаться обычной
  таблицей, чтобы его можно было задавать словарём).
- Новые колонки реестра: `event`, `reference`, `type_source`.
- `type_source` (`explicit` / `inferred` / `dictionary` / `default`) — явно
  заданное значение автовывод не перезаписывает.
- Сеттеры `set_role()`, `set_type()`, `set_outcome()`, `set_predictor()`.

Дальше по маршруту: `apply_dictionary()` (метаданные таблицей — требование
пользователя), селекторы, план, движок описательных, сравнение групп.

## Известные пробелы

- `bind_rows()` и joins берут реестр **первого** аргумента; метаданные второго
  игнорируются молча. Слияния реестров с выявлением конфликтов нет.
- Дубликаты имён столбцов отвергает `tibble::as_tibble()` своей ошибкой, а не
  нашей `bq_error_*`. Единообразия типизации ошибок тут нет.
- Порог `max_levels = 20` в `infer_type()` произволен.
- Кодировка 1/2 (частая в выгрузках SPSS) не распознаётся как двухуровневая.
- `haven_labelled` не обрабатывается: `labelled` в зависимости не входит.
- Ролей пока нет словаря; в заголовке они сортируются по алфавиту.
